## Phase 1 — Security hardening · ~2.5 days (incl. CORS/Expo regression testing)

- **🔴 Password hashing:** replace hand-rolled PBKDF2 (`core/auth.py:17-31`) with `passlib[bcrypt]` `CryptContext` (dep already in requirements). Migration path: `verify_password` tries bcrypt first, falls back to legacy PBKDF2 salt:hash format, transparently rehashes on successful login. Fixes the timing-leak string compare too.
- **🔴 Privilege escalation:** `auth.py:26` — ignore client `role`; everyone registers as `inspector`; `admin`/`auditor` only via seeded admin script.
- **🔴 Auth on all audit endpoints:** `require_current_user` on `/api/scans` list/detail/delete/PDF, **`/api/stats` explicitly**, `POST /api/products` (admin-only), `/api/scans/sync` (+ dedup by `clientScanId`). Anonymous *scan creation* stays allowed via soft auth; audit data is never anonymously readable/deletable.
- **CORS:** `main.py:27` — use `CORS_ORIGINS` from config (already parsed at `config.py:82`, never used); then regression-test Expo web + Android emulator + LAN device against the allowlist.
- **Uploads:** magic-byte MIME sniff + extension allowlist (jpg/png/webp) + 10 MB cap + sanitized extension (`scans.py:98`).
- **JWT:** fix deprecated naive `datetime.utcnow()` in `create_access_token` (`core/auth.py:36`) → timezone-aware; add password minimum length; rate-limit `/api/auth/*` and `/api/scan` (slowapi).

## Phase 2 — Accuracy program · ~4-5 days (incl. dataset curation buffer)

**2.1 Ground truth + eval harness — schema first**
- Define `eval/ground_truth.json` schema before writing the harness:
```json
{"image": "eval/images/scan_abc.jpg",
 "fields": {"net_quantity": {"value": "500 g", "status": "pass"},
            "mrp": {"value": "₹45", "status": "pass"},
            "fssai": {"value": "12345678901234", "status": "pass"}},
 "expected_overall": "pass"}
```
- Dataset: the 12 existing scans + new photos (target 50+ images, 15+ categories), hand-labeled.
- `scripts/eval_accuracy.py`: per-field precision/recall/F1 + status-decision accuracy → `eval/report.md`. Baseline measured before any extraction change; rerun after each.

**2.2 Extraction fixes (each verified via harness)**
- MRP: OCR-variant tolerance (₹→? misreads, "Rs" split from amount, value on next line); missing "incl. of all taxes" = warning not fail.
- Net qty: unit whitelist per Rule 6(1)(c) (`gms`/`ltr`/`ML` → warning, non-standard).
- FSSAI: real 14-digit structural validation (currently just length ≥10 at `field_extractor.py:224`).
- Dates: extend dot-matrix fusion (`0CT`→OCT exists; add `1UN`→JUN etc.), MM/YY vs MM/YYYY disambiguation, with unit tests.
- Origin: domestic-address inference validated against harness; mandatory-only-for-imports rule mapping from verified citations.

**2.3 Unify pipelines — delete `ScanService` entirely, but keep the load-bearing modules**
- Rewrite `/api/scans/sync` as a thin wrapper over `pipeline.ensemble_pipeline.ensemble_scan` (same engines, same columns, `user_id` attached, files to `UPLOAD_DIR` not cwd-relative `./uploads`).
- **Port first, then delete:** the CB2 `field_validators.py` logic (confidence-gated `needs_review`, MRP tax-inclusion check, net-qty unit validation) is better than the live path's found=pass rule — port it into the unified pipeline (satisfies 2.4), then delete: `app/services/scan_service.py`, `app/ocr/paddle_engine.py` (its mock-token fallback fabricates OCR text when PaddleOCR fails to load — `paddle_engine.py:69-91`), `app/ocr/easyocr_engine.py`, `app/ocr/ensemble.py`, `app/validation/rule_engine.py`, `app/validation/field_validators.py`, `app/vision/*`.
- **KEEP (live pipeline imports them):** `app/ocr/engine_base.py` (TextPolygon — `field_extractor.py:4`), `app/extraction/reading_order.py` + `declaration_parser.py` (`field_extractor.py:5-6`). Do not delete `app/extraction/` wholesale — it would break the build.
- Update `tests/test_rules.py`, `test_ocr_ensemble.py`, `test_pipeline_extraction_rules.py` (they import CB2 modules; several become port-coverage tests).

**2.4 Honest confidence**
- Field confidence = OCR conf × engine agreement (already computed in `declaration_parser`); `needs_review` band (<0.60) wired through the unified pipeline so low-confidence extractions never auto-PASS; surfaced in API + UI.

## Acceptance criteria

- **P0:** Backend down + production mode → zero mock data anywhere, clear errors; demo mode shows banner everywhere; one rule DB, spot-checked citations match gazette; `GET /api/stats` without token → **401**.
- **P1:** Register with `"role": "admin"` → response role `inspector`; legacy PBKDF2 user can log in and is rehashed to bcrypt; CORS restricted list verified from Expo web + Android emulator.
- **P2:** ≥90% per-field F1 on ground truth (baseline measured first); same image via `/api/scan` and `/api/scans/sync` → **identical `status` and every `fields[*].status`**.
- **P3:** Refresh keeps login; offline scan syncs; PDF downloads with auth; notes persist via PATCH; all screens have loading/error/empty states.
- **P4:** `alembic upgrade head` on fresh DB works; `alembic downgrade -1` then `upgrade head` on test DB loses no data; docker compose up → working system; no repo-root artifacts.
- **P5:** New dev runs end-to-end from README alone; no doc claim contradicts code.

**Execution order:** P0 (0.3→0.4→0.5→0.2→0.1) → P1 → P2 → P3 → P4 → P5, committing per workstream; pytest after each backend change, eval harness after each extraction change.
